# XShield 使用说明书（v1.0 稳定版）

X(Twitter) 评论区垃圾拦截 + 触发名单自动拉黑 + 社区共享黑名单。

> 本说明书对应扩展版本 **1.0.0+**。旧版本（≤0.8）说明书已归档于 Git 历史。

---

## 一、安装

1. 构建扩展（或直接使用已构建的 `apps/extension/dist`）：

   ```
   corepack enable
   pnpm install
   pnpm build
   ```

2. Chrome 打开 `chrome://extensions` → 右上角开启**开发者模式** → **加载已解压的扩展程序** → 选择 `apps/extension/dist`。

3. 点击工具栏 XShield 图标 → **打开面板**。面板侧栏底部显示当前版本号。

> 拉黑功能依赖当前 Chrome 已登录 x.com（读取登录 Cookie ct0）。未登录时只能过滤，不能拉黑。
> **更新扩展后，已打开的 X 页面需刷新一次**才会注入新脚本（Chrome 机制）。

## 二、核心模型（先读懂这一段）

```
关键词命中
  → 该回复立即隐藏，作者进入「触发记录」（= 待拉黑名单）
  → 进入自动拉黑队列，有 30 分钟缓冲期
      ├─ 你什么都不做 → 缓冲期过后按风控节奏自动拉黑
      ├─ 点「白名单」→ 永久豁免，立即出队
      ├─ 点「删除」→ 删记录并出队
      └─ 点「拉黑」或全选「拉黑列表(N)」→ 立即执行（跳过缓冲期）
  → 拉黑成功 → 移入「已拉黑」，此后该用户永不重复处理
```

**触发记录页就是待拉黑名单**，全扩展唯一一份。词库只有一个（云端 + 本地自定义两层），不存在"自动拉黑词"与"普通词"之分——所有命中一视同仁。

## 三、页面导览（五页）

### 1. 触发记录（= 待拉黑名单）

- 卡片：昵称 / @handle / 触发原因 / 时间 / 回帖内容；点昵称跳转其 X 主页
- 状态徽标「**排队中**」= 已在自动执行队列里（缓冲期或等待轮询）
- 每卡三个按钮：**拉黑**（立即执行）/ **白名单**（永久豁免并出队，记录离开列表）/ **删除**（删记录并出队）
- 工具栏：全选、搜索、触发原因筛选、**拉黑列表(N)**（3 秒内二次点击确认）
- 工具栏下方：**拉黑节奏设置**（每日上限 / 每批数量 / 单次间隔秒），改动即时生效

### 2. 拉黑记录

- 统计：今日自动拉黑 / 剩余（队列中）/ 已拉黑用户（累计）
- **近 7 天拉黑**按日统计
- 已拉黑数据库视图：默认展示**最新 300 个**（每页 100，共 3 页），更早的用**搜索**（匹配 handle 与昵称）定位后解除；卡片带拉黑时间
- 每张卡片：**白名单**（解除拉黑并加白，误拉恢复）/ **解除拉黑**（只解除）

### 3. 白名单

手动增删。白名单用户：永不触发、永不入队、已在队列中的立即出队。

### 4. 规则与同步

- **云端词库**：显示词数、最近同步时间；点「立即同步」拉取（GitHub API → jsDelivr CDN → 内置词库三级兜底）；词标签可单条**禁用**（×）
- **本地词库**：添加 / **编辑**（铅笔图标，Enter 保存 Esc 取消）/ 删除 / 导入 / 导出
- 词格式：一行一条；普通词不区分大小写子串匹配；正则写 `/pattern/flags`，如 `/比.{0,3}她.{0,3}好/i`
- 词库源在总设置（留空 = 默认清洗仓库 `smthdagg/XShield-keywords`）

### 5. 总设置

- 总开关、屏蔽回帖 / 高亮切换、过滤开关（同时查用户名、仅评论区、特殊字符、纯 emoji、Grok 卡）
- 词库源 owner/repo、语言
- **GitHub Token + 共享拉黑名单到项目仓库**（见第六节）
- **导出诊断信息**：一键下载 JSON 快照（版本、各名单数量与内容、同步状态、最近 100 条日志）——报障时先发这个

## 四、自动拉黑与风控

默认节奏（触发记录页可调）：每日 300、每批 30（批后歇 15 分钟）、单次间隔 5 秒 ±5 秒抖动、429 暂停 15 分钟、瞬时失败 5 次指数退避、账号注销/被封直接放弃。

要点：

- 所有拉黑走你当前 Chrome 的 X 登录会话，效果与手动在网页上拉黑完全一致
- 队列按**用户**去重：同一用户刷到多少次都只处理一次
- 触发记录按**推文**记：同一用户的多条垃圾推会各记一条（留证），不重复入队
- X 未公布官方拉黑频率限制，默认值是保守经验值；老号可适度放宽（如间隔 3 秒、每日 500），新号建议保持默认

## 五、社区共享黑名单

把大家拉黑的垃圾账号汇总成一份共享名单，全员互通：

- **下载（全员自动）**：同步时一并拉取项目仓库的 `handles.txt`，命中的账号隐藏回复并进入待拉黑队列（理由标记「社区共享」）
- **共享（可选，需 Token）**：总设置填 GitHub Token（需对词库仓库有 Contents 写权限）→ 点「共享拉黑名单到项目仓库」→ 你账本里的 handle 合并上传（去重，不覆盖他人数据）
- **退出**：删除「社区共享」记录 = 永久排除该 handle；白名单同样豁免
- 不填 Token = 只下载，你的任何数据不会上传

## 六、词库自助维护（不需要找维护者）

三件事全部在面板内自助完成：

1. **下载**：规则与同步 → 立即同步（另有 6 小时自动同步）。
2. **本地加词**：规则与同步 → 我的词库 → 添加/编辑/删除（仅自己生效）。
3. **发布到云端（全员生效，需 Token）**：
   - 在总设置填 GitHub Token。获取方法（Fine-grained 细粒度令牌，最小权限）：
     GitHub 头像 → Settings → Developer settings → Personal access tokens →
     Fine-grained tokens → Generate new token；Resource owner 选自己，
     Repository access 选 **Only select repositories** 并只勾
     `smthdagg/XShield-keywords`，Permissions 里仅把 **Contents** 设为
     **Read and write**（其余保持 No access），生成后复制 `github_pat_` 开头的
     令牌粘贴进面板。该 Token 只能读写这一个仓库的文件内容，可随时撤销；
   - 规则与同步页点「**同步我的词库到项目仓库（覆盖远端）**」——面板当前显示的词库视图（云端词 − 禁用 + 本地自定义）就是发布内容，删除也是有意的；
   - 之后所有用户下次同步即拿到新词。

提示：面板同步优先走 GitHub API（编辑后立即生效）；CDN 兜底通道可能有短暂缓存，可在 [purge.jsdelivr.net](https://www.jsdelivr.com/tools/purge) 手动刷新。

## 七、词库维护（项目所有者）

- 内容词：仓库 `keywords.txt`（561 行清洗版：中文词 + 品牌词 + `t.cn`/`Gate Card` + 7 条结构正则）
- 共享黑名单：仓库 `handles.txt`（由共享按钮累积）
- 改完可直接在 GitHub 网页提交，顺手到 [purge.jsdelivr.net](https://www.jsdelivr.com/tools/purge) 刷一下缓存；用户端下次同步生效

## 八、常见问题

| 现象 | 处理 |
|------|------|
| 更新扩展后 X 页面不触发 | 刷新页面（Chrome 注入机制）；或 F12 看控制台有无 `[XShield] content vX ready` |
| 点白名单没反应 | 0.8.1 已修；重载扩展确认版本号 |
| 待拉黑数字一直为 0 | 正常——队列是流水线，缓冲期过后逐个执行；积压时才显示大于 0 |
| 触发记录列表是空的 | 名单都在「排队中/已拉黑」里了，切筛选查看 |
| 已拉黑用户找不到了 | 列表只显示最新 300 个，用搜索定位更早的用户 |
| 拉黑失败：无法获取身份凭证 | 登录 x.com 后重试 |
| 拉黑失败：HTTP 429 | 触发限流，自动暂停 15 分钟 |
| 想撤销误拉 | 拉黑记录页该卡片「白名单」= 解除拉黑并加白 |
| 面板行为怪异 | 总设置 → 导出诊断信息 → 把 JSON 发给维护者 |

## 九、隐私

全部数据（词库、触发记录、队列、账本、白名单、设置）保存在本地 `chrome.storage.local`（unlimitedStorage）。网络请求仅三类：云端词库/黑名单拉取、GitHub 共享上传（主动点击 + Token）、X 拉黑接口（触发/手动操作）。详见 [PRIVACY.md](PRIVACY.md)。
