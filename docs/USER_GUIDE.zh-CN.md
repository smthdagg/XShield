# XShield 使用说明

## 1. 安装

### 加载已构建插件

1. 打开 Chrome。
2. 访问 `chrome://extensions`。
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择 `apps/extension/dist`。
6. 将 XShield 固定到 Chrome 工具栏。

### 从源码构建

需要 Node.js 20+ 和 pnpm 9+。

```bash
corepack enable
pnpm install
pnpm build
```

构建后加载 `apps/extension/dist`。

## 2. 创建规则

进入 Dashboard 的“规则”页面，创建关键词或正则规则。

- `keyword`：普通关键词，一行一个。
- `regex`：正则表达式，一行一个。
- 匹配字段：用户名、显示名、自我介绍、帖子内容。
- 分数：命中后增加的风险分。
- 规则可新增、编辑、保存、取消、删除。

命中后，X 页面中的相关帖子会变成浅黄色，并且用户进入候选池。

## 3. 复核候选用户

进入“候选用户”页面：

- 查看头像、用户链接、自我介绍、粉丝信息、命中原因。
- 确认目标后加入拉黑队列。
- 误触发用户加入白名单。
- 支持全选、多选、删除、加入白名单。

## 4. 执行拉黑队列

进入“拉黑队列”页面：

- “执行队列”：按设置里的每批数量、间隔时间和模式执行。
- “手动立即拉黑”：跳过时间间隔限制，但仍按批量处理。一次拉黑过多可能影响账号安全。
- “停止/执行”：控制自动队列是否暂停。
- “删除选中”：从队列移除。
- “选中加白”：从队列移除并加入白名单。

## 5. 导出已拉黑用户

进入“已拉黑用户”页面，选择导出格式后点击“导出已拉黑用户”。

支持格式：

- TXT：简单用户名清单。
- CSV：适合 Excel、WPS、Google Sheets。
- JSON：适合程序读取。
- NDJSON：适合日志系统或流式处理。
- SQL：适合导入数据库前做二次处理。

## 6. 设置

- 语言：跟随系统、简体中文、繁体中文、英文、日语、韩语、法语。
- 规则模式：自动或手动。
- 拉黑模式：模拟或真实。
- 分数阈值：候选命中分数阈值。
- 每批数量：单批处理人数。
- 间隔分钟：自动执行间隔。
- 最大重试：失败后的重试次数。
- 失败冷却：连续失败后的等待时间。

## 7. 真实拉黑说明

真实拉黑依赖当前 Chrome 中的 X/Twitter 登录状态。若 X 更新网页接口、登录状态、CSRF 策略或页面结构，功能可能暂时失效。

建议：

- 先用模拟模式熟悉流程。
- 设置合理批量，例如每批 50 到 100 人。
- 设置至少 10 分钟以上的间隔。
- 不要频繁使用“手动立即拉黑”。
- 使用者自行承担账号安全、平台规则和当地法律合规责任。

## 8. 常见问题

### 搜索搜不到人

先打开 X 搜索页或相关帖子页面，让扩展采集可见用户。手动搜索主要在已采集用户和 X 可见搜索结果中工作。

### 真实拉黑失败

检查：

- 是否已登录 X。
- 设置里是否为“真实”模式。
- 队列里是否有 `queued` 用户。
- Dashboard 日志里是否有认证失败、接口失败、用户不存在或 ID 不匹配提示。

### 为什么跳过很多用户

常见原因：

- 用户不存在。
- 已经拉黑。
- 用户 ID 和用户名不匹配。
- 已加入白名单。
- 本地已记录为已拉黑。
